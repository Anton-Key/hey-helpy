## Утро: запустить (за 60–30 минут до выхода)

### 1. Свежие демо-данные — Refresh demo

1. GitHub → репозиторий → вкладка **Actions** → слева **«Refresh demo»** → справа **Run workflow** → ветка `main` → зелёная кнопка **Run workflow**.
2. Открыть появившийся запуск → жёлтая плашка **Review deployments** → отметить `production-db` → **Approve and deploy**.
3. Ждать зелёную галочку (1–2 минуты). Внизу запуска, в **Summary**: «✅ Демо-история перезалита», таблица «Demo Properties» — **около 94 заявок** и до 18 визитов (числа немного плавают — это нормально).
4. ⚠️ Refresh demo **удаляет все тестовые заявки** «Demo Properties» (созданные на репетиции). Поэтому всё, что готовите «заранее» (пункт 4 ниже), — **после** этого запуска, а после него Refresh demo уже не запускать.

### 2. Логи функций — живы ли ИИ и бот

Supabase → ваш проект → слева **Edge Functions** → выбрать функцию → вкладка **Logs**. Каждая строка — одно обращение, вида `{"fn": "…", "status": …, …}`. Сначала сделайте по одному пробному действию (см. пункт 3), потом смотрите:

| Функция | Хорошая строка | Плохие признаки |
|---|---|---|
| `voice-intake` (голос → заявка) | `"status":200`, `"model":"pro"` (основная модель; `"lite"` — запасная, тоже ок), `"layer":true`, `"place":true`, `"ms"` — до ~5000 | `"status":502` и `"code":"timeout"` / `"network"` / `"http_5…"` — ИИ Яндекса не ответил (приложение само разберёт по словарю); `"status":500`, `"code":"not_configured"` — не заданы секреты Yandex |
| `photo-identify` (камера / фото) | `"status":200`, `"model":"main"`, `"kind":"ac"` (кондиционер, внутренний блок), `"candidates"` ≥ 1, `"ai_ms"` — до ~8000 | `502` с `"code":"timeout"` — модель зрения не ответила за 14 с; `400` с `"code":"too_large"` / `"bad_image"` — снимок не тот |
| `telegram-bot` (бот) | `"status":200`, `"who":"guest"`, `"type":"cmd_start"` и `"result":"start_object"` после QR; `"type":"text"` / `"voice"`, `"ai":true` после сообщения | `"status":401` с `"code":"bad_secret"` / `"no_secret"` — вебхук не подключён или секрет другой (запустить «Telegram webhook» → `set`); `"code":"not_configured"` — нет токена бота |
| `telegram-notify` (уведомление гостю) | `"status":200`, `"result":"sent"` или `"sent_photo"` | `"result":"send_failed"` — Telegram не принял; `"not_visible"` (404) — заявку не видно этому пользователю |
| `telegram-notify` (шаг 28: «Новая заявка» исполнителю) | `"result":"assigned"`, `"sent":1` | `"sent":0` — у исполнителя не привязан Telegram, он написал боту `/stop` или 0025 не применена; `"failed":1` — Telegram не принял (исполнитель заблокировал бота) |
| `telegram-bot` (шаг 28: «Взять в работу») | `"action":"take"`, `"result":"taken"` | `"result":"not_executor"` — нажал не исполнитель подрядчика; `"unavailable"` — 0025 не применена |
| `offline-sync` (без сети) | `"status":200` после возврата связи | `401` — не вошёл; фото без сети в акте будут «отпечаток не сверен» |

Текста заявок, фото и имён в логах нет — так задумано.

## Сцена «Исполнитель без сети» (шаг 27) — как её провести

1. Телефон 1: **включить режим полёта**.
2. Открыть заявку (ту, что создали заранее с телефона 2) → **«Начать работу»** → отметить **визит** → пройти **чек-лист** → **фото «после»** (живой камерой, со штампом) → **«На проверку»**.
3. Вверху — плашка **«Нет сети — сохранено на телефоне: N действий»**. Фраза: «Подвал, связи нет — исполнитель всё равно закрывает работу, телефон всё запомнил.»
4. **Выключить режим полёта** → через несколько секунд плашка **«Отправлено ✓»**.
5. Ноутбук: открыть заявку → «На проверке», фото «после», в карточке — «снято без сети · время по GPS ✓» → **«Принять»** (менеджер — не тот, кто сдавал, база это разрешает).
6. Телефон 2: бот присылает **«Заявка № … выполнена ✅»** с фото «после».
