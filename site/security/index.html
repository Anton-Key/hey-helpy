Security and deployment

In Hey Helpy permissions are enforced by the database. The interface only shows what is allowed.

Company isolation

  • Company data is separated by PostgreSQL row-level security policies — on every table.
  • Companies and managers of different sites are isolated — everyone sees only their own information.
  • A new user without an invitation sees nothing: people join a company with an invitation code (valid for 7 days).

Roles and segregation of duties

  • Roles: administrator, manager (whole company or an access zone), contractor technician, requester.
  • A role or company can only be changed through checked database functions, not by editing a profile.
  • Only a technician of the assigned contractor starts and submits work; someone else accepts it. Roles table.
  • An internal permissions review (October 2026) found several issues within a company; fixes have been released and applied.

Files, log, AI

  • Photos, documents, floor plans and acts are kept in private storage; no public links, only temporary links for those with access.
  • Work order history and action times are written by the database. The log of role, zone and crew changes is visible to the administrator and cannot be edited.
  • AI keys live only on the server. Models are called with the user’s permissions; model output is checked against the company’s reference data.
  • Server logs never contain work order texts, model answers or recognition shots — only technical data (time, size, error code).
  • The Telegram bot does not expose chat IDs to the app; employees’ phone numbers are visible only to the person and managers.
