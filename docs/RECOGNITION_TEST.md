# Тест точности распознавания оборудования — памятка

Раздел в приложении: **Profile → My company → Recognition test** («Профиль → Моя компания → Тест распознавания»). Виден только администратору компании. Работает в браузере и на Android.

Зачем: в материалах для инвесторов стоит цель «точность распознавания ≥ 95 % на тесте из 300–500 фото». Этот раздел даёт честную цифру с размером выборки и погрешностью: «Top-1: 93.4% (95% CI 90.1–95.7%), n = 352 photos, 41 units, 12 rooms, 3 sites». Какая получится — такую и показываем.

## Перед началом (один раз)
1. Миграция **0028** применена (Actions → Apply migration → `0028_recognition_eval.sql`).
2. Функции выложены: Actions → **Deploy functions** (в списке теперь 6 функций, новая — `recognition-eval`).
3. В приложении вы — **администратор** компании.

## Как собрать 300–500 фото
1. **Выберите 2–3 реальных объекта** (офис, склад, отель — где есть доступ) и **30–50 единиц оборудования** на них.
2. **Перед съёмкой внесите оборудование в реестр** (карточка объекта → «Оборудование» → добавить или импорт из Excel), укажите вид (кондиционер, фанкойл, светильник…) и **поставьте точку на плане этажа**. Фото размечается по реестру помещения: чего нет в реестре — того не выбрать.
3. **На каждую единицу — 8–10 фото**:
   - спереди и сбоку;
   - близко, средне, далеко;
   - хороший свет и полумрак (если можно — против света);
   - пара кадров, где оборудование частично закрыто.
4. **Обязательно — помещения, где несколько похожих единиц** (два одинаковых кондиционера в одной комнате). Это самый честный тест: по одной картинке их не различить, и отчёт покажет это отдельной строкой «Similar units in the room».
5. **20–30 фото оборудования, которого нет в реестре** (выберите «Not in the registry»). Проверка, что ИИ не выдумывает: если он уверенно называет единицу из реестра — это «ложное узнавание».
6. **В кадр не должны попадать люди, лица и документы.**

## Как снимать в приложении
1. **Add photo** → выберите объект и помещение.
2. **Take photo** (на Android — камера; в браузере — **Upload photo**, файл с компьютера).
3. **What is in the photo** — отметьте сами: единицу из реестра помещения или «Not in the registry». ИИ на этом шаге **не запускается**, его ответ не влияет на разметку.
4. **Shooting conditions** — свет, расстояние, ракурс, «частично закрыто».
5. **Save and take next** — серия: та же единица и условия остаются, сразу открывается камера для следующего кадра (удобно снять 8–10 ракурсов подряд). Поменяйте условия, если они изменились. **Save** — сохранить и выйти.
6. Ошиблись с разметкой — **Photos in the set** → удалить фото и снять заново (пока набор не заморожен). Изменить разметку уже сохранённого фото нельзя — так задумано.

Набор **dev / test** приложение не выбирает и вы тоже: база сама кладёт примерно 30 % единиц в dev (для настройки), 70 % — в test (итоговая цифра). Все фото одной единицы — в одном наборе, чтобы не было «подсказки» между наборами. Счётчик показывает, сколько фото, единиц, помещений, объектов и сколько осталось до 300.

## Итоговый замер
1. Когда фото набрано достаточно — **Freeze test set** (подтверждение: после этого фото набора нельзя добавлять, менять и удалять; новые фото пойдут в новый набор).
2. По желанию сначала — **Run on dev** (это для настройки, не для инвесторов).
3. **Final run on test** — приложение отправляет фото пачками (по 3 одновременно, с повторами при сбое сети). Прогресс виден. Если ИИ на каком-то фото не ответил — «Retry AI errors»; оставшиеся ошибки считаются **неверными** ответами.
4. Если подключены два поставщика ИИ (секреты `AI_*` и `YANDEX_*`) — в строке **AI provider** можно выбрать, кого проверять. Каждый прогон — один поставщик и одна модель.
5. Откройте прогон → **Report (PDF)** и **Data (CSV)** → пришлите отчёт.

## Что в отчёте
- **Top-1** — главная цифра: ИИ первой назвал именно ту единицу, что на фото. С 95 % доверительным интервалом (интервал Уилсона) и n.
- **Top-3** — правильная единица среди трёх кандидатов.
- **Equipment type** — угадан хотя бы вид (кондиционер / фанкойл / светильник…).
- **False recognitions** — фото оборудования «не из реестра», где ИИ всё равно назвал единицу из реестра.
- **По порогу уверенности** — при пороге X: на какой доле фото ИИ «отвечает сам» и какая у него точность. ИИ отвечает, если балл первого кандидата не ниже порога и не равен второму; иначе — спрашивает человека. Это основа правила «не уверен — спроси человека».
- Разбивка: по видам, «несколько похожих в помещении / одна такая», свет, расстояние, ракурс, «закрыто».
- Время ответа: медиана и 95-й процентиль. Токены на фото. Стоимость — поставщики в ответе её не сообщают, поэтому «not reported».
- 6 примеров ошибок с миниатюрами (только фото своей компании).
- Строка: «Measured on the company's own test set; test set frozen on <date>; no tuning on test photos».

## Правила честного замера
1. Подсказку и настройки подбираем **только на dev**. На test — только итоговый прогон.
2. После заморозки test-набор не меняется. Новые фото — в новый набор.
3. В материалах для инвесторов — **только цифра с test**, с n и интервалом.
4. Цифру ниже 95 % не прячем: пишем как есть и что улучшаем.
5. Реальные фото — только в закрытом хранилище `eval-photos` компании, **не в репозитории**.

## Как это устроено (для разработчиков)
- База — миграция `0028_recognition_eval.sql`: наборы, фото, прогоны, результаты; закрытое хранилище `eval-photos`; всё — только администратор своей компании. dev / test, «похожие в помещении» и вид единицы ставит база при вставке. Прогон создаёт `recognition_eval_run_start` (test — только замороженный набор), закрывает `recognition_eval_run_finish`, результаты пишет только `recognition_eval_put_result` (service_role).
- Функция `supabase/functions/recognition-eval/` распознаёт фото **тем же кодом**, что «Узнать по фото» у пользователя (`_shared/identify_run.ts`: подсказка, модель, справочники под RLS, сопоставление с реестром; контекст — объект и помещение фото), язык подсказки — английский. Версия подсказки — SHA-256 подсказки, схемы ответа, каталога видов и баллов сопоставления.
- Метрики — `_shared/eval_metrics.ts` (тесты `recognition-eval/metrics_test.ts`).
- Приложение — `lib/features/recognition_eval/`.
- Локальная сквозная проверка (без рабочей базы и без настоящего ИИ): `bash tools/db_test/run.sh`, затем `POSTGREST=<postgrest> node tools/e2e/recognition_eval.mjs [--shots]`.
