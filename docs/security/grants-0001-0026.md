# Права Data API на таблицы 0001–0026 — заготовка (шаг 31)

**Это не миграция и не файл для запуска сейчас.** Рабочая база в порядке: таблицы 0001–0026 получили права по старым правилам Supabase (автоматически), правило с 30.10.2026 их не затрагивает.

## Зачем заготовка
С 30 октября 2026 Supabase не выдаёт новым таблицам схемы `public` права для Data API (`anon`, `authenticated`, `service_role`) автоматически. Если схему когда-нибудь создавать **миграциями с нуля** — self-hosted Supabase в Yandex Cloud для РФ, новый проект, ветка предпросмотра (branching), — таблицы 0001–0026 окажутся без прав, и приложение получит «permission denied» на всём.

Тогда сразу после 0026 нужна одна миграция «права на таблицы 0001–0026» — текст ниже. Номер — следующий свободный на тот момент; в рабочую базу её применять не нужно (вреда не будет — grant повторно ничего не меняет).

Откуда текст: снят с локальной базы `tools/db_test/run.sh` (все миграции 0001–0026 по порядку, права как в Supabase до 30.10.2026) — ровно те права, что есть сейчас, только действия Data API (`select / insert / update / delete`; `truncate`, `references`, `trigger` приложению не нужны и не выдаются). Права **по столбцам** (`telegram_*` без `chat_id` — 0018, `profiles` / `companies` — обновление только своих полей, 0003 / 0011) сохранены. Что разрешено строкам — по-прежнему решают RLS и триггеры, права только пускают к таблице.

Проверка после применения на новой базе — тот же тест `tools/db_test/grants.sql`.
