### D. «Refresh demo» — `.github/workflows/refresh-demo.yml`
7. Только `workflow_dispatch`. Задача `guard` (без базы) падает, если ветка не `main` — до запроса одобрения.
   Задача `refresh`: `environment: production-db`, `permissions: contents: read`.
   - Проверка секретов `SUPABASE_DB_URL`, `DEMO_MANAGER_EMAIL`, `DEMO_EXECUTOR_EMAIL`, `DEMO_REQUESTER_EMAIL`,
     `DEMO_ELEC_EXECUTOR_EMAIL`: пустой (или из одних пробелов) — понятная ошибка **до** подключения к базе;
     каждое значение — `::add-mask::`. Части строки подключения тоже скрываются (как в «Apply migration»).
   - Копия `demo_history.sql` в `$RUNNER_TEMP` без строк `begin;` / `commit;` (ожидается ровно две, иначе
     ошибка) — транзакцию открывает сам `psql --single-transaction`.
   - Email передаются **psql-переменными** (`-v manager_email=…`) в отдельный файл настроек
     (`set_config('demo.manager_email', :'manager_email', false)` — `:'…'` безопасно экранирует кавычки),
     вывод скрыт `\o /dev/null`. Запуск: `psql "$SUPABASE_DB_URL" -v ON_ERROR_STOP=1 --single-transaction -f настройки -f копия`.
   - В конце — select: число заявок и визитов компании «Демо БЦ» → в лог и в `$GITHUB_STEP_SUMMARY`.

   **Как поправлен `demo_history.sql`.** Подставить `:'var'` прямо в файл нельзя: внутри блока `do $$ … $$`
   psql переменные не подставляет. Поэтому четыре email в блоке 2 теперь такие:
   ```sql
   v_manager_email text := coalesce(nullif(current_setting('demo.manager_email', true), ''),
                                    'manager@example.com');
   ```
   (так же `executor`, `requester`, `elec_executor` — у последнего по умолчанию `''`).
   В SQL Editor настроек `demo.*` нет → `current_setting(…, true)` даёт пусто → действует email, вписанный
   в файл, как раньше: замените `example.com` на свои и нажмите Run. Остальной скрипт не менялся.
   Выражение проверено запросом только на чтение к рабочей базе (без настройки — значение по умолчанию;
   компания «Демо БЦ» найдена, одна). Шаги workflow прогнаны локально без базы: подготовка файлов,
   проверка секретов (пустой → ошибка, все заполнены → дальше), синтаксис bash всех шагов, YAML всех workflow.
8. В `CLAUDE.md` — раздел «Перезаливка демо-данных (Refresh demo)», упоминание PR check в «Порядке работы».

## Что сделать руками

1. **Секреты для Refresh demo** — GitHub → Settings → Environments → `production-db` → Environment secrets →
   Add secret, четыре штуки (значения — email демо-пользователей, те же, что в `.env.demo`):
   - `DEMO_MANAGER_EMAIL`
   - `DEMO_EXECUTOR_EMAIL`
   - `DEMO_REQUESTER_EMAIL`
   - `DEMO_ELEC_EXECUTOR_EMAIL` — исполнитель «ЭлектроПро» (четвёртый пользователь). Обязателен: без него
     workflow остановится. Если такого пользователя нет — создайте его в Supabase → Authentication → Users.
2. **Обязательная проверка PR** — после merge (когда «PR check» хотя бы раз пройдёт, GitHub узнает имя `check`):
   Settings → Rules → Rulesets → `protect-main` → включить **Require status checks to pass** → Add checks →
   `check` (из «PR check») → Save.
3. **Запуск Refresh demo** (перед питчем): Actions → **Refresh demo** → Run workflow (Branch: `main`) →
   Run workflow → дождаться «Review deployments» → `production-db` → **Approve and deploy** → в Summary
   запуска — число заявок и визитов «Демо БЦ».
4. Посмотреть в PR скриншоты (`docs/screens/latest/`) — вкладка Files changed.

## Ограничения и что осталось

- «PR check» запустится сам на этом же PR — результат будет виден в PR (Checks). Локально те же команды прошли.
- «Refresh demo» не запускался ни разу (только вы) — первый запуск проверит подключение и секреты.
  Если упадёт — база не изменится (одна транзакция), текст ошибки — в логе шага «Перезалить демо-историю».
- Refresh demo обновляет только записи демо-истории (25 заявок, визиты). Тестовые заявки, созданные руками
  (например «2e12e21e»), он не удаляет — их можно удалить в приложении (отменить) или в SQL Editor.
- `DEMO_ELEC_EXECUTOR_EMAIL` сделан обязательным (как в задании), хотя сам скрипт умеет работать и без него.
- На 412 «Отчёты» — карточки, а не таблица с прокруткой: так было и раньше, ничего не обрезано.
- Таблица на 1280 по-прежнему шире экрана на 1–2 столбца — они доступны прокруткой (полоса видна).
