# Шаг 11: голосовая заявка — распознавание речи на устройстве и разбор по словарю

Ветка `step-11`. **Миграций нет**, база не менялась. Ни один workflow не запускался.

## Что сделано

### A. Распознавание речи вместо записи файла
1. **Пакет `record` заменён на `speech_to_text`.** Раньше приложение записывало звук в файл и отдавало его
   заглушке (`MockVoiceIntake` всегда возвращал одну и ту же фразу про кондиционер). Теперь речь превращается
   в текст средствами платформы: в браузере — Web Speech API (Chrome, Edge, Safari), на Android — системный
   распознаватель. Ключей и своего сервера не нужно, но нужен интернет (звук обрабатывает Google / Apple).
2. **`SpeechInput`** (`speech_input.dart`) — общий интерфейс: «начать», «остановить», текст по ходу речи,
   громкость. Язык речи — по языку интерфейса (`ru-RU` / `en-US`).
3. **Экран «Слушаю»** (`voice_record_screen.dart`) переписан: распознавание начинается сразу после нажатия
   «Нажми и говори», текст виден по мере речи. Остановка — кнопка «Готово», пауза 3 секунды или 30 секунд
   общего времени. Подсказка «После паузы в 3 секунды закончу сам».
4. **Понятные ошибки** — отдельный текст на каждый случай, с кнопками «Ещё раз» и «Ввести текстом»:
   - браузер без распознавания (Firefox) / на телефоне нет сервиса распознавания;
   - нет доступа к микрофону — отдельная инструкция для браузера (значок замка → Микрофон → Разрешить,
     для iPhone — Настройки → Safari) и для телефона (Настройки → Приложения → … → Микрофон);
   - нет связи с сервисом распознавания;
   - ничего не услышали.
5. **«Ввести текстом»** — запасной путь: поле для текста → «Далее» → тот же разбор и тот же экран
   подтверждения. Заявка уходит с каналом `text` (а не `voice`), на экране — «Вы написали».
6. **Android:** в манифест добавлен `<queries>` с `android.speech.RecognitionService` — без него на
   Android 11+ приложение не видит системный распознаватель. Разрешение `RECORD_AUDIO` уже было.

### B. Разбор текста в поля заявки — локально, без ИИ
`TextIntake` (`text_intake.dart`) раскладывает текст в черновик:
- убирает «Эй, Хелпи» / «Hey, Helpy» в начале (и частые ошибки распознавания: «хей хелп», «hey happy»…);
- **заголовок** (до 60 символов) и **описание** (весь текст с заглавной буквы и точкой);
- **вид работ (слой)** — по словарю `TextIntake.layerRules`: основы слов на русском и английском с весами
  (3 — называет оборудование, «кондиционер»; 2 — типичная жалоба, «жарко»; 1 — намёк). Побеждает слой с
  наибольшей суммой. Слои: Климат, Электрика, Сантехника, Системы безопасности, Клининг, Мебель;
- **место** — помещение по совпадению слов из названий помещений и по этажу, иначе объект;
- **срочность** — слова «срочно», «авария», «потоп», «очень жарко»… → высокая; «не срочно», «когда будет время» → низкая.

Новые слова добавляются только в этот словарь; после правки — `flutter test test/text_intake_test.dart`.

### C. Подготовка к шагу 12 (ИИ-разбор)
`VoiceIntakeClient` теперь принимает **текст**, а не аудиофайл. Сейчас работает `LocalVoiceIntake`
(разбор выше). На шаге 12 рядом появится `ServerVoiceIntake` — Edge Function с YandexGPT (ключи только на
сервере); при ошибке сети приложение откатится на локальный разбор. Формат ответа описан в коде.

### D. Экран подтверждения
- Если разбор узнал помещение или объект — они сразу выбраны в списке.
- Подсказка «Заголовок и описание можно поправить перед отправкой».
- На широком экране — колонка до 640 px по центру (раньше растягивалась на всю ширину).
- Справочники (слои, помещения), загруженные для разбора, передаются дальше — второй раз не грузятся.

### E. Режим без микрофона для скриншотов
Флаг `--dart-define=VOICE_MOCK=true`: вместо микрофона «произносится» заготовленная фраза
(«Эй, Хелпи, в переговорной на третьем этаже не работает кондиционер, очень жарко»), а разбор — настоящий.
Включается только в `/screens` (в Playwright нет микрофона). В рабочие сборки не добавлять.

## Что проверить в приложении

1. **Телефон (APK):** Заявки → большая кнопка с микрофоном → при первом запуске разрешить микрофон →
   сказать «В переговорной на третьем этаже не работает кондиционер, очень жарко» → замолчать на 3 секунды.
   Ожидается: текст появляется по ходу речи, затем «Проверьте заявку»: вид работ «Климат», помещение
   «Переговорная», срочность «Высокая». Поправить заголовок → «Отправить».
2. **Браузер Chrome:** то же самое на веб-версии. Браузер спросит доступ к микрофону — разрешить.
3. **Запрет микрофона:** запретить доступ → должна появиться понятная инструкция, где его включить.
4. **«Ввести текстом»:** на экране ошибки нажать «Ввести текстом», написать «срочно протечка в туалете на
   2 этаже» → «Далее» → «Сантехника», высокая срочность, вверху «Вы написали».
5. **Английский язык:** переключить язык в Настройках, сказать «The lights are flickering in the lobby» →
   вид работ «Электрика» (Electrical).
6. **Firefox** (если есть): вместо «Слушаю» — сообщение, что браузер не умеет распознавать речь, и
   «Ввести текстом».

## Ограничения и что не сделано

- **Разбор — по словарю, без ИИ.** Фразы без ключевых слов («что-то странно гудит») оставят вид работ
  пустым — пользователь выберет сам. Умный разбор YandexGPT — шаг 12.
- **Нужен интернет**: и браузер, и Android отправляют звук в облако Google / Apple. Для РФ позже —
  Yandex SpeechKit.
- **Ключевая фраза «Эй, Хелпи» без нажатия кнопки** пока не работает — только кнопка «Нажми и говори»
  (фраза в начале речи просто убирается из текста). Porcupine — позже.
- На некоторых Android без приложения Google нет системного распознавателя — будет сообщение и
  «Ввести текстом».
- В Safari на iPhone распознавание требует включённой диктовки (Настройки → Основные → Клавиатура).
