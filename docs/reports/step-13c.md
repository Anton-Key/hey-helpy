## Что сделано (по пунктам задания)

### A. Строка фильтров
Под поиском, над сегментами «Все / Открытые / Просрочено» — строка «таблеток» с прокруткой
вбок. Обычная таблетка белая со стрелкой вниз. Выбранная — мятная, с краткой подписью выбора
(«Критический +1») и ✕. **Выбранные таблетки встают в начало строки**, чтобы на телефоне их было
видно без прокрутки.

1. **Период**: «Сегодня», «7 дней», «30 дней», «Этот месяц», «Прошлый месяц», «Свой период…»
   (календарь «с — по»: на телефоне на весь экран, на ПК — карточкой по центру).
   Сверху переключатель «По дате создания / По сроку». Подпись: «7 дней», «Срок: Сегодня»,
   «1 окт. – 9 окт.».
2. **Объект** (несколько). Если выбран ровно один объект, появляется таблетка **Помещение** (несколько).
   При выборе второго объекта помещения сбрасываются сами.
3. **Подрядчик** (несколько) + «Без подрядчика».
4. **Срочность** (несколько, с цветными точками).
5. **Статус** (несколько, капсулами `StatusPill`) + «Просрочено» первым пунктом.
6. **Вид работ** (несколько, слои компании на языке интерфейса).
7. **Ещё**: Тип (разовая / повторяющаяся), Источник (голос / текст / вручную), «Нужно фото»,
   «Возвращались на доработку», «Создал я», «Назначено мне» (только у исполнителя).
8. **Сортировка** справа от строки: «Сначала новые» (по умолчанию), «Сначала старые», «По сроку»,
   «По срочности», «По статусу», «По объекту». На телефоне — только значок ⇅ (иначе таблетка
   занимает полстроки), на ПК — значок и название. Выбор сразу применяется.

Окно выбора: на узком экране — шторка, на широком (≥ 900) — выпадающее окно под таблеткой.
В окне — галочки, поиск по списку (если пунктов больше 7), кнопки «Сбросить» и «Применить (N)».
В конце строки — «Сбросить всё», если что-то выбрано. Над списком — «Найдено N из M».

### B. Логика
9. **`OrderFilter`** (`lib/features/requests/order_filter.dart`) — один неизменяемый класс
   (фильтр + сортировка + сегмент), только чистые функции:
   - `serverConditions` — условия запроса к серверу (`in`, `is.null`, `gte`/`lt`, `gt`, `eq`, `or`).
     **Фильтруются на сервере все поля фильтра**. Поиск и сегмент считаются в памяти: так счётчики
     сегментов видят всё, что подошло под фильтр;
   - `matches` — та же проверка в памяти (повторно после сервера; тесты сверяют её с условиями сервера);
   - `sortOrders`, `groupOrders`, `buildOrderList` (фильтр + поиск + сегмент + счётчики);
   - `toQuery` / `fromQuery` / `serialize` — адрес страницы и сохранение;
   - подписи таблеток — `OrderFilterLabels` в `order_filter_bar.dart`.

   Тесты — `test/order_filter_test.dart` (30): каждое поле отдельно и все вместе (условия сервера
   и проверка в памяти согласны), «Свой период» (включительно, порядок дат, без дат), «Без подрядчика»
   (отдельно и вместе с подрядчиками), «Просрочено» (отдельно и со статусами), несколько групп «или»,
   каждая сортировка (в том числе «без срока — в конце», «без объекта — в конце»), группы, сегменты
   и поиск поверх фильтра, сохранение туда-обратно, мусор в адресе, подписи таблеток.
10. **Сегменты** — быстрые пресеты поверх фильтра. Счётчики на них учитывают фильтр и поиск.
11. **Карта → «Заявки»** теперь просто ставит фильтр «Объект» (та же таблетка, снимается ✕).
    Старой плашки «Объект: …» больше нет.
12. **Группы**: «Сначала новые / старые» — «СЕГОДНЯ / РАНЕЕ»; «По срочности» — по срочности;
    «По статусу» — по статусу («ПРОСРОЧЕНА» первой); «По объекту» — по объекту; «По сроку» — без
    групп, зато под названием заявки виден срок.
13. **Запоминается** на устройстве (`shared_preferences`, отдельно для каждого пользователя:
    ключ `orders_filter.<id пользователя>`). В вебе фильтр дублируется в адресе:
    `https://anton-key.github.io/hey-helpy/#/?pri=critical&st=overdue&obj=…&sort=due`.
    Открытие такой ссылки применяет фильтр (ссылка важнее сохранённого). Ссылка работает и после входа:
    параметры запоминаются при запуске, до перехода на экран входа.
14. **Права не менялись**: запрос идёт под RLS, фильтр только сужает то, что пользователь и так видит.
    Варианты (объекты, подрядчики, слои, помещения) — из тех же справочников под RLS.
15. **Пусто** — «Ничего не найдено» + кнопка «Сбросить фильтры» (снимает фильтры, сегмент и поиск;
    сортировка остаётся). Если заявок нет совсем — прежнее «Пока нет заявок».

## Как проверить руками (веб или APK, вход менеджером «Демо БЦ»)
1. **Просроченные критические по «ТЦ «Демо Плаза»»**: «Объект» → «ТЦ «Демо Плаза»» → Применить;
   «Срочность» → «Критический»; «Статус» → «Просрочено». Ожидается 1 заявка «Нет света в фуд-корте».
   Появилась таблетка «Помещение» — в ней 3 помещения Плазы.
2. **Повторяющиеся** (после Refresh demo): «Ещё» → «Повторяющаяся» → Применить. Ожидаются 2 заявки
   с пометкой «· регламент». «Разовая» — все остальные.
3. **Свой период**: «Период» → «Свой период…» → выбрать, например, 1–5 число прошлой недели →
   «Сохранить» → «Применить (1)». На таблетке — даты. Переключить «По сроку» — считаются сроки.
4. **По сроку**: справа ⇅ (на ПК — «Сначала новые») → «По сроку». Сверху — ближайшие сроки
   (просроченные первыми), заявки без срока — в конце, под названием виден срок.
5. **Ссылка коллеге (веб)**: настроить фильтр → скопировать адрес из строки браузера → открыть в другом
   окне или отправить коллеге. Фильтр тот же. Пример: `…/hey-helpy/#/?pri=critical,high&sort=priority`.
6. **Запоминание и сброс**: настроить фильтр → закрыть приложение → открыть снова: фильтр на месте.
   Зайти другим пользователем — у него свой фильтр. «Сбросить всё» в конце строки снимает всё,
   кроме сортировки. Фильтр, под который ничего не подходит, — «Ничего не найдено» и «Сбросить фильтры».
7. **Карта**: «Локации» → «Карта» → объект → «Заявки». Открывается список с таблеткой «Объект».
8. **Исполнитель**: «Ещё» → «Назначено мне» (видно только исполнителю).

## Индексы (миграцию не делал, рекомендации на будущее)
В базе уже есть индексы по `company_id`, `(company_id, created_at desc)`, `object_id`, `location_id`,
`assigned_contractor_id`, `assigned_executor_id`, `created_by`, `layer_id`, `status` (проверено
запросом только на чтение). Для текущих объёмов (десятки–сотни заявок) этого хватает. Когда заявок
станут тысячи, стоит добавить отдельной миграцией:
- `create index if not exists idx_wo_company_due on public.work_orders (company_id, due_at) where status not in ('done','cancelled');`
  — «Просрочено», период и сортировка «по сроку»;
- `create index if not exists idx_wo_company_status_created on public.work_orders (company_id, status, created_at desc);`
  — статус + период по дате создания (самая частая пара).

Отдельные индексы на `priority`, `input_channel`, `requires_photo`, `recurrence` не нужны: у этих полей
мало разных значений, и они всегда идут вместе с `company_id`.

## Ограничения и что не сделано
- Фильтр «Вид работ» ищет по `layer_id`. Старые заявки, где есть только текст `work_type` без
  `layer_id` (до шага 4), под него не попадут. В демо таких нет.
- «Назначено мне» = назначена мне лично **или** моему подрядчику без конкретного исполнителя (то есть
  не коллеге). В демо поле «исполнитель» у заявок пустое, поэтому у демо-исполнителя показываются все
  заявки его подрядчика.
- В окне «Статус» поиска нет, хотя пунктов 8 (> 7): список постоянный и короткий.
- «Применить (N)»: N — сколько пунктов выбрано в окне, а не сколько заявок найдётся (это видно в
  «Найдено N из M» после применения).
- Адрес в браузере обновляется без новой записи в истории (кнопка «Назад» не перебирает фильтры).
  Если роутер сам сменит адрес (например при выходе), параметры из адреса пропадут, но фильтр
  останется сохранённым на устройстве.
- Сортировка выполняется в памяти (на сервере — только порядок «сначала новые»), чтобы «По статусу»
  и «По объекту» работали так, как задано.
