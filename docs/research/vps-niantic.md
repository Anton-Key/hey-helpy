# VPS-эксперимент: Niantic Spatial NSDK 4 + VPS2 (шаг 28)

**Что это.** Отдельный APK `hey-helpy-vps.apk`: навёл камеру в отсканированной переговорной → телефон узнаёт, где он, с точностью до сантиметров (VPS) → над реальным кондиционером висит табличка «КД-301 · 1 открытая заявка · ТО 31.10». Табличка держится на месте при ходьбе **и после перезапуска** — в отличие от WebXR-страницы шага 25, где метка жила только до закрытия вкладки.

**Статус на 15.10.2026:** сборка проходит (локально — `flutter build apk --release -PwithVps=true`, 70,7 МБ; в CI — workflow «Build APK (VPS experiment)»). На телефоне **не проверялось** — у Claude Code нет устройства. Показывать на питче — только если владелец проверит на телефоне к воскресенью (см. «Проверка» ниже).

Основное приложение и основной APK **не изменились**: без флага `-PwithVps=true` модуль `:vps` не подключается, NSDK не скачивается, канал `hey_helpy/vps` не регистрируется, кнопок VPS нет.

## 2. Что сделано

### Сборка (изоляция)
- `android/settings.gradle.kts` — `include(":vps")` **только** при `-PwithVps=true`.
- `android/build.gradle.kts` — репозиторий NSDK только при флаге и только для группы `com.nianticspatial`.
- `android/app/build.gradle.kts` — при флаге: `implementation(project(":vps"))`, `applicationIdSuffix = ".vps"` (ставится **рядом** с основным приложением), источники `src/vps/kotlin`; без флага — `src/novps/kotlin` (пустой `VpsHook`).
- `android/vps/` — модуль: `VpsActivity`, `VpsApi` (REST), `VpsContract`, чистые `PoseMath` / `VpsToken` / `VpsState` + JUnit-тесты (12), `consumer-rules.pro` (R8 не трогает Filament / SceneView / ARCore; NSDK приносит свои правила).
- `.github/workflows/build-apk-vps.yml` — «Build APK (VPS experiment)», только вручную: JUnit → `flutter build apk --release -PwithVps=true --target-platform android-arm64` → артефакт `hey-helpy-vps-apk` (файл `hey-helpy-vps.apk`); из `main` — ещё релиз `latest-vps-apk` (постоянная ссылка). «Build Android APK» и «PR check» от NSDK не зависят.

### Токен
- Developer token — **только секрет GitHub `NIANTIC_DEV_TOKEN`**. Сборка берёт его из переменной окружения и кладёт в `BuildConfig.NIANTIC_TOKEN` модуля `:vps`; в репозитории и в логах его нет.
- ⚠️ **Токен внутри APK можно извлечь.** Для демо допустимо: токен живёт ≤ 90 дней, у него только scope «VPS API», отзывается в портале за минуты. Niantic прямо пишет: «Do not bundle developer tokens into public releases» — для продакшна нужна выдача токенов сервером (п. 5).
- Экран сам проверяет срок (поле `exp` в токене): «Токен VPS истёк — обновите в портале Niantic и пересоберите VPS-APK»; за 7 дней до конца — предупреждение «Токен VPS истекает через N дн.».

### Экран «Метки VPS (эксперимент)» (`VpsActivity`, Kotlin)
- Открывается из Flutter по каналу `hey_helpy/vps` (`status` / `open`), кнопки — **только в VPS-сборке**: «Камера-помощник» (помещение из «Где я») и шторка помещения на плане этажа.
- Flutter передаёт: адрес базы, anon-ключ, токен сессии пользователя, `location_id`, язык, право менеджера, подписи меток (название, «1 открытая заявка · ТО 31.10», цвет системы) и **все тексты экрана** из `lib/l10n` (в Kotlin своих строк нет; тест сверяет ключи).
- Экран сам читает скан помещения и метки — REST Supabase с JWT пользователя, всё под RLS 0025, без service-ключей.
- «Найти место» → `trackAnchor(anchor payload)` → индикатор **красный «Ищу… медленно ведите камерой по комнате» / жёлтый «Примерно» / зелёный «Точно ✓»**. Зелёный — только когда якорь помещения в состоянии `TRACKED` (так советует документация VPS2: решать по состоянию якоря, а не устройства).
- Когда хоть раз было «Точно» — над оборудованием появляются таблички (рамка цвета системы, название, строка про заявки и ТО). Таблички — Android-View поверх камеры, спроецированные из 3D-точки (`PoseMath.project`); размер — по расстоянию; дальше 15 м не рисуются.
- Касание таблички → «Карточка оборудования» (экран закрывается, Flutter открывает карточку) / «Удалить метку» (менеджер).
- Менеджер: «Поставить метку» → касание по стене / полу (hit-test ARCore: плоскости горизонтальные **и вертикальные**, точки глубины) → «Какое это оборудование?» → метка сохраняется **относительно якоря**: `метка_отн = якорь⁻¹ ∘ точка` (`PoseMath.relativeTo`), показ — `якорь ∘ метка_отн`. После перезапуска система координат ARCore другая, а якорь — то же место в комнате, поэтому метка встаёт туда же (тест `markFollowsAnchorAfterRestart`).
- Понятные сообщения: нет токена / истёк, Niantic не принял токен (`AUTH_FAILURE`), нет ARCore, нет доступа к камере, нет сети, лимит запросов (`QUOTA_EXCEEDED`), скан не найден (`NO_MAP_FOUND`), «ведите медленнее» (`BAD_TRACKING`), сессия истекла (401), не нашёл поверхность.
- Камера и запросы VPS — только пока экран на виду (`onPause` останавливает трекинг: экономия кредитов). Камера Flutter выключается до запуска ARCore.

### Хранение — миграция 0025, раздел 1
- `vps_sites` — скан помещения: компания и объект (заполняет база из помещения), помещение (или этаж), название, `anchor_payload` (8–20 000 знаков, пробелы убираются), кто / когда. Один скан на помещение. **Видят** менеджеры (своей зоны 0016) и исполнители подрядчиков, закреплённых за объектом или с заявкой на нём; заявитель — нет. Меняют — менеджер с правом на объект / администратор.
- `vps_marks` — метка: скан, оборудование (того же объекта — проверяет база), позиция xyz (м, |x|,|y|,|z| ≤ 50) и поворот (единичный кватернион), кто / когда. Одна метка на оборудование в скане (переставить = upsert). **Видят** те, кто видит оборудование (`can_see`); ставят / удаляют — `can_manage` (менеджер с системой оборудования в зоне, администратор).
- Старая `ar_anchors` (0002) не тронута; не используется и **заменяется** этими таблицами (удалить — отдельной миграцией после эксперимента).
- Тесты — `tools/db_test/vps.sql` (25 проверок) + изоляция компаний (`tenant_isolation.sql`).

### Во всех сборках (Flutter)
- План этажа → помещение → **«VPS-скан помещения»** (менеджер): вставить anchor payload из портала, название, «Сохранить», «Удалить скан». Без 0025 — «Нужна миграция 0025». Остальные роли — только просмотр.
- ⚠️ Отдельной «карточки помещения» в приложении нет — её роль играет шторка помещения на плане, поэтому строка там.

## 3. Что нужно от владельца (пошагово)

1. **Аккаунт.** https://scaniverse.nianticspatial.com → бизнес-аккаунт (бывшие аккаунты Lightship переносятся туда же). План **Free**: 20 000 кредитов в месяц, 5 мест. Расход: обработка скана с телефона — 30 кредитов за секунду видео (1 800 в минуту, 5-минутный скан = 9 000); один запрос локализации VPS — 12 кредитов. Итого Free ≈ 10 минут съёмки в месяц **или** ≈ 1 600 запросов VPS (экран шлёт ~1 запрос в секунду при поиске и 1 раз в 5 с после). **Коммерческих прав на Free нет** — только Pro ($50/мес) или Enterprise.
2. **Developer token.** Scaniverse web → слева **Credentials → Developer Tokens → New developer token** → имя (например `hey-helpy-demo`) → срок **90 дней** → scope **VPS API** → **Create** → **сразу скопировать** (показывается один раз).
   Затем GitHub → репозиторий → **Settings → Secrets and variables → Actions → New repository secret** → Name `NIANTIC_DEV_TOKEN`, Secret — вставить токен → **Add secret**. Никуда больше токен не писать (ни в чат, ни в issue).
3. **Скан переговорной** (приложение Scaniverse на **iPhone** — бизнес-сценарий сейчас только на iOS; вход «Sign in with Business Account»):
   - **+** → новый Site («БЦ Демо · 301 Переговорная») → Confirm.
   - Свет — **такой же, как будет на показе** (включённые лампы, те же шторы).
   - Держать телефон вертикально на уровне глаз, вести **медленно и плавно**; снять все стены, мебель, кондиционер **с 2–3 углов**; не снимать пустой пол и белые стены вплотную.
   - Один проход 2–3 минуты (до 5 мин и 500 м² на скан); для надёжности — **2 перекрывающихся прохода** (по часовой и против).
   - После остановки — **Localize** прямо в Scaniverse: не нашлось — переснять до загрузки.
4. **Обработка и payload.** Scans → **Upload All** → выбрать сканы → **Generate Assets** → Confirm (от нескольких минут до часа) → Assets → «⋯» → **Set as Production** (без этого приложение скан не увидит). Проверка: Assets → **Localize** на месте.
   Anchor payload — строка у production-ассета (в SDK это `asset.vpsData.anchorPayload`). ⚠️ Где именно кнопка копирования в веб-портале, я проверить не мог (нужен вход). Если в портале её не видно — поставить официальный пример `nsdk-samples-kotlin`, раздел **Sites**: в подробностях ассета строка «VPS Anchor: …» — это и есть payload.
5. **В приложении** (обычном или VPS): менеджером → объект «БЦ «Демо»» → этаж 3 → помещение «301 Переговорная» → **VPS-скан помещения** → вставить payload → Сохранить.
6. **Сборка VPS-APK.** GitHub → **Actions → «Build APK (VPS experiment)» → Run workflow** (ветка `main`) → ~10–15 мин → страница запуска → Artifacts → `hey-helpy-vps-apk` (zip с `hey-helpy-vps.apk`); из `main` — ещё постоянная ссылка: https://github.com/Anton-Key/hey-helpy/releases/download/latest-vps-apk/hey-helpy-vps.apk. Поставить на Android-телефон **с ARCore** (список: https://developers.google.com/ar/devices), разрешить установку из неизвестных источников. Приложение появится вторым значком с тем же названием — это VPS-версия.
7. **Проверка** (в переговорной, с интернетом):
   1. Войти менеджером → план этажа 3 → переговорная → **Метки VPS (эксперимент)** → разрешить камеру и геопозицию.
   2. **Найти место** → медленно вести по комнате → красный → жёлтый → **«Точно ✓»** (зелёный). Первый ответ иногда до минуты.
   3. **Поставить метку** → коснуться кондиционера на экране → «Кондиционер КД-301» → «Метка сохранена» → табличка над кондиционером.
   4. Отойти на 3–4 м, обойти комнату — табличка на месте.
   5. **Закрыть**, смахнуть приложение из недавних, открыть заново → «Найти место» → «Точно ✓» → табличка снова над кондиционером (±несколько см).
   6. Коснуться таблички → «Карточка оборудования» → открылась карточка КД-301.
   7. Войти исполнителем КлиматСервис → то же место → таблички видны, «Поставить метку» нет.
8. **Что прислать Claude:** видео экрана (запись экрана Android) пунктов 2–6; если не работает — текст сообщения на экране и примерно на каком шаге; модель телефона. Токен **не присылать**.

## 4. Ограничения и риски
- **Не проверено на устройстве.** Возможны: другой порядок инициализации NSDK на конкретном телефоне, медленная первая локализация (до 60 с по документации), смещение табличек на несколько сантиметров по высоте (табличка — на 15 см выше точки касания).
- Таблички — 2D поверх камеры (проекция 3D-точки), не 3D-модель: при взгляде сбоку не «поворачиваются». Для демо это нагляднее и надёжнее, чем 3D-материалы Filament.
- Только arm64 (NSDK так поставляется). Размер VPS-APK ~71 МБ (NSDK 24 МБ, Filament ~6 МБ).
- Кредиты Free-плана: ~1 600 запросов VPS в месяц — на репетиции и показ хватит, на ежедневную работу нет.
- После **пересъёмки** помещения (новый payload) старые метки привязаны к старому якорю — их нужно поставить заново (приложение предупреждает).
- Токен сессии пользователя передаётся в экран на время открытия (живёт ~1 час): на долгом экране — «Сессия истекла — закройте экран и откройте заново».
- Flutter предупреждает, что модуль `:vps` применяет Kotlin Gradle Plugin (в будущих версиях Flutter — «Built-in Kotlin»). Сейчас это предупреждение, не ошибка; основной APK его не видит.

## 5. Переход на продакшн (только описание)
1. **Сервисный аккаунт** в Scaniverse web (Service accounts) → API-ключ хранится **только на сервере** (секрет Supabase Edge Functions, например `NIANTIC_SERVICE_KEY`).
2. Новая Edge Function `vps-token` (`verify_jwt = true`): проверяет пользователя и что ему вообще положен VPS (роль, объект в зоне) → `POST https://spatial-identity.nianticspatial.com/oauth/token` с `{grantType: "exchange_api_key_access_token", apiKey}` → отдаёт приложению `accessToken` (JWT) и `expiresAt`. Лимит выдачи на пользователя; в логе — без токенов.
3. Приложение перед открытием экрана берёт токен у функции и передаёт его в `VpsActivity`; NSDK — `NSDKSession.setAccessToken(...)` при обновлении (за минуту до `expiresAt`). Developer token из APK убирается совсем.
4. **Коммерческий план** (Pro или Enterprise) — права на коммерческое использование; бюджет кредитов: 12 кредитов за запрос → на объект с 20 показами в день по ~30 запросов ≈ 216 000 кредитов в месяц — это уже Enterprise / докупка.
5. Скан делает подрядчик по сканированию или менеджер объекта (iPhone), payload вносится тем же экраном «VPS-скан помещения». Для многих помещений — импорт payload по Sites API (список production-ассетов организации).
6. Данные: сканы помещений клиента хранятся у Niantic — нужно согласие клиента и проверка по 152-ФЗ / политике клиента (для РФ — отдельный вопрос, VPS Niantic в РФ может быть недоступен).

## 6. Как собрать локально
```
flutter build apk --release -PwithVps=true --target-platform android-arm64 \
  --dart-define=SUPABASE_URL=… --dart-define=SUPABASE_ANON_KEY=…
# токен — переменной окружения (не в команде, не в файле в репозитории):
# NIANTIC_DEV_TOKEN=… flutter build apk …
cd android && ./gradlew -PwithVps=true :vps:testDebugUnitTest   # чистые функции
```
На машине с 7 ГБ памяти проектный `org.gradle.jvmargs=-Xmx8G` роняет демон — локально помогает `~/.gradle/gradle.properties` с `-Xmx3g` (в репозиторий не кладётся).
